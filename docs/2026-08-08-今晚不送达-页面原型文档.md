# 今晚不送达 页面原型文档

## 文档信息
- 项目名称：今晚不送达
- 文档类型：页面原型文档
- 版本：V1.0
- 日期：2026-08-08
- 适用范围：Web / H5 MVP 版本

---

## 1. 原型目标

本页面原型文档用于指导《今晚不送达》MVP 页面设计与交互落地，帮助设计、开发或原型工具快速实现首版产品。

本产品核心闭环为：
**首页浏览 → 商家选品 → 购物车 → 确认订单 → 模拟支付 → 配送等待 → 结果结算**

设计目标：
1. 让用户获得接近真实外卖点单的熟悉体验。
2. 在关键节点明确“模拟点单”边界。
3. 通过等待页拖住冲动。
4. 通过结果页完成成果反馈。

---

## 2. 全局设计规范

### 2.1 页面风格
- 整体风格参考主流外卖产品的信息密度与结构习惯。
- 视觉氛围偏夜间、克制、轻健康化，不做强烈搞笑风。
- 优先移动端单列布局。

### 2.2 全局导航建议
MVP 可不做完整底部 Tab。
建议保留：
- 返回按钮
- 页面标题
- 购物车浮层入口

### 2.3 全局文案原则
- 不羞辱
- 不说教
- 不夸张制造焦虑
- 拟真但清晰
- 结果导向

### 2.4 关键说明文案
以下说明必须至少在支付页出现一次：

> 本次为模拟点单，不会产生真实交易，也不会有真实商家接单。

## 3. 页面原型详细说明

---

## 页面 1：首页 / 夜宵推荐页

### 1. 页面目标
让用户一打开就进入“正在逛外卖”的熟悉心智，而不是感觉自己在一个传统减肥工具里。

### 2. 页面结构
#### 顶部区域
- 页面标题：今晚想吃点什么？
- 副标题：可以先点，但不一定要真的吃到
- 搜索框占位：搜奶茶 / 炸鸡 / 烧烤 / 蛋糕

#### 品类快捷入口区
建议用 2 行图标入口：
- 炸鸡
- 奶茶
- 烧烤
- 汉堡
- 甜品
- 夜宵小吃

#### 推荐商家列表区
每张商家卡片包含：
- 商家封面图
- 商家名称
- 评分
- 月售
- 预计送达时间
- 起送价
- 配送费
- 满减文案
- 招牌商品标签

#### 弱提示入口区
可放在首页中部或底部：
- 今晚先别真的点
- 嘴馋但不想破功
- 今晚忍住一单

### 3. 页面交互
- 点击品类进入对应品类页。
- 点击商家卡片进入商家页。
- 页面下拉滚动浏览推荐商家。

### 4. 设计重点
- 首页 90% 像外卖平台，10% 像控卡工具。
- 控卡意图不能太强，否则用户难以沉浸。

### 5. 推荐按钮文案
- 去看看
- 今晚先逛逛
- 进入商家

---

## 页面 2：品类页

### 1. 页面目标
承接不同夜间食欲场景，让用户聚焦于某一类想吃的东西。

### 2. 页面结构
#### 顶部栏
- 返回按钮
- 页面标题：炸鸡 / 奶茶 / 烧烤等

#### 筛选标签区
可做静态标签：
- 深夜爆单
- 高热量快乐
- 最多人想点
- 奶茶脑袋

#### 商家列表区
延续首页卡片样式。

### 3. 页面交互
- 点击商家进入商家页。
- 顶部返回回到首页。

### 4. 设计重点
- 保持与首页一致的卡片结构。
- 不需要做复杂筛选逻辑，MVP 做静态展示即可。

---

## 页面 3：商家页

### 1. 页面目标
这是最关键的沉浸式点单页面，需要让用户真实地产生“我已经在选吃的”感觉。

### 2. 页面结构
#### 商家头部
- 商家封面图
- 店名
- 评分
- 月售
- 预计送达时间
- 公告文案
- 满减活动标签

#### 菜单主体区
左侧分类栏：
- 招牌推荐
- 单人套餐
- 小食
- 饮品
- 加料区

右侧商品列表：
每个商品卡片包含：
- 商品图
- 商品名
- 一句话简介
- 月售
- 价格
- 预估热量（弱提示）
- “+”加购按钮

#### 底部购物车悬浮栏
包含：
- 已选商品数量
- 当前金额
- 差几元满减提示
- 去结算按钮

### 3. 页面交互
- 点击商品卡片或“+”按钮进入商品详情弹层。
- 加购成功后，购物车金额与数量实时更新。
- 点击底部购物车进入购物车页或弹层。

### 4. 设计重点
- 商品卡片的信息密度要接近真实外卖产品。
- 热量提示不要过重，建议放成灰字：约 420 kcal。
- 凑单感可以保留，但不要无限刺激加购。

### 5. 推荐文案
- 招牌爆款
- 深夜高热量快乐
- 今天最容易失守的那一口

---

## 页面 4：商品详情弹层

### 1. 页面目标
通过规格选择与加料操作提升真实点单感。

### 2. 页面结构
- 商品图
- 商品名
- 商品简介
- 基础价格
- 规格选择区
- 加料选择区
- 温度 / 辣度 / 甜度选择区（按品类出现）
- 数量选择器
- 底部加入购物车按钮

### 3. 规格示例
#### 奶茶类
- 温度：常温 / 少冰 / 去冰 / 热
- 甜度：全糖 / 半糖 / 三分糖 / 无糖
- 加料：珍珠 / 椰果 / 芋圆

#### 炸鸡类
- 份量：小份 / 大份 / 双人份
- 口味：香辣 / 蒜香 / 蜂蜜黄油

### 4. 页面交互
- 用户必须完成必要规格选择后才可加入购物车。
- 数量增减实时更新金额。
- 点击加入购物车后关闭弹层。

### 5. 设计重点
- 规格选择项要足够生活化。
- 这是提升拟真感的重要一环。

---

## 页面 5：购物车页 / 购物车浮层

### 1. 页面目标
让用户形成“订单已经快成立”的拥有感。

### 2. 页面结构
- 已选商品列表
- 每项商品的规格说明
- 数量调节按钮
- 商品小计
- 打包费
- 配送费
- 优惠金额
- 应付总额
- 去结算按钮

### 3. 页面交互
- 支持商品数量 + / -。
- 数量归零时移除该商品。
- 金额、优惠、总价联动更新。
- 点击去结算进入确认订单页。

### 4. 设计重点
- 可以保留“再差 ¥3 可享满减”的弱凑单提示。
- 但不要做无限推荐链条，避免反向刺激真实食欲。

### 5. 推荐文案
- 已加入今晚冲动清单
- 这份快乐已暂存

---

## 页面 6：确认订单页

### 1. 页面目标
把点单流程推进到临门一脚，让用户感觉“订单已基本成型”。

### 2. 页面结构
#### 地址信息区
- 地址昵称：家 / 公司 / 宿舍
- 详细地址：可使用预设模拟地址
- 联系方式：可省略真实号码

#### 配送信息区
- 配送方式：立即送出
- 预计送达：25～35 分钟
- 高峰期提示

#### 商品明细区
- 商品列表
- 规格说明
- 数量
- 小计

#### 费用汇总区
- 商品金额
- 打包费
- 配送费
- 优惠金额
- 应付总额

#### 备注区
输入框占位建议：
- 少辣
- 到了打电话
- 放门口别敲门

#### 底部按钮区
- 按钮：去模拟支付

### 3. 页面交互
- 地址使用预设，无需真实定位。
- 备注可自定义输入。
- 点击按钮进入模拟支付页。

### 4. 设计重点
- 备注区非常重要，会显著增强“我真在下单”的沉浸感。
- 页面整体应保持像真实外卖确认订单页。

---

## 页面 7：模拟支付页

### 1. 页面目标
完成整条链路中最关键的替代动作：支付。

### 2. 页面结构
#### 顶部区
- 页面标题：确认支付
- 支付金额

#### 支付方式区
- 微信支付（模拟）
- 余额支付（模拟）

#### 边界说明区
使用小字但可见：
> 本次为模拟点单，不会产生真实交易，也不会有真实商家接单。

#### 底部主按钮
- 确认模拟支付

### 3. 点击后的状态
点击按钮后依次出现：
1. loading 动画
2. 文案：订单生成中…
3. 文案：正在匹配虚拟骑手…
4. 自动跳转等待页

### 4. 设计重点
- 页面整体仍然应接近真实支付页风格。
- 但“模拟支付”四个字必须明确可见。
- 不允许调用真实支付能力。

---

## 页面 8：配送等待页

### 1. 页面目标
这是整款产品的核心干预页面，用于拖住用户、延长冲动窗口、降低即时下单欲望。

### 2. 页面结构
#### 订单状态卡片
- 订单编号
- 当前状态
- 预计送达时间

#### 虚拟骑手卡片
- 骑手头像
- 骑手昵称
- 骑手评分

#### 配送进度区
MVP 推荐：
- 进度条
- 4 个状态节点
  1. 商家备餐中
  2. 骑手已接单
  3. 正在赶往你的位置
  4. 即将送达

#### 倒计时区
- 剩余时间：04:32
- 预计送达时间：22:48

#### 文案轮播区
建议滚动显示：
- 这份夜宵正在被安全延迟
- 你已经撑过最想下单的前几分钟
- 再坚持一会儿，这一单就会变成成果

### 3. 页面交互
- 页面自动倒计时。
- 状态随时间自动切换。
- 倒计时结束后自动跳转结果页。
- MVP 不提供跳过按钮。

### 4. 设计重点
- 等待时长建议 3～5 分钟。
- 页面不能太空，要持续给用户一种“流程还在进行”的感觉。
- 文案要从拟真逐渐过渡到成果导向。

---

## 页面 9：结果结算页

### 1. 页面目标
将“最终没有收到外卖”的落差感，重新解释为“成功完成一次控卡”。

### 2. 页面结构
#### 主结果卡片
- 本次成功拦截：1 单夜宵
- 避免摄入：824 kcal
- 节省金额：¥36
- 等待时长：4 分 12 秒

#### 等价换算区
示例：
- 约等于少吃了 2.3 个汉堡
- 约等于少跑了 70 分钟有氧

#### 累计战绩区
- 累计拦截：18 单
- 累计避免：12,480 kcal
- 累计节省：¥642
- 连续守住：6 晚

#### 底部 CTA 区
- 今晚收工
- 再逛一次
- 查看战绩（若已做战绩页）

### 3. 页面交互
- 页面加载时自动结算本次成果。
- 自动更新累计战绩。
- 点击按钮可返回首页或进入战绩页。

### 4. 设计重点
- 结果页是整个产品的价值兑现页。
- 必须让用户感觉“我不是白忍了”。
- 数据展示应成为主角，而非纯搞笑文案。

### 5. 推荐文案
- 本次成功避免摄入 824 kcal
- 你没有失去一份外卖，你拿回了一次选择权
- 这单没有送到嘴里，但送到了你的目标里

## 页面 10：战绩页（P1 可选）

### 1. 页面目标
承接长期复用价值，帮助用户看到自己不是一次成功，而是在持续积累。

### 2. 页面结构
- 累计拦截单数
- 累计避免热量
- 累计节省金额
- 连续守住天数
- 历史记录列表
- 常点品类分布（P1）

### 3. 页面交互
- 从结果页进入。
- 查看历史战绩后可回到首页。

### 4. 设计重点
- MVP 可暂不实现此页。
- 若做，建议结构简洁，以数据卡片为主。

## 4. 页面跳转关系

### 主路径
首页 → 品类页 / 商家页 → 商品详情弹层 → 购物车 → 确认订单页 → 模拟支付页 → 配送等待页 → 结果结算页 → 首页 / 战绩页

### 返回路径
- 品类页返回首页
- 商家页返回首页或品类页
- 确认订单页返回购物车/商家页
- 支付页返回确认订单页
- 结果页返回首页

- 文案：先挑几样今晚最想点的

### 5.2 加购成功状态
- 文案：已加入今晚冲动清单

- 订单生成中…
- 正在匹配虚拟骑手…

### 5.4 等待页状态切换
- 商家备餐中
- 骑手已接单
- 正在赶往你的位置
- 即将送达

### 5.5 结果结算状态
- 成功拦截 1 单夜宵
- 避免摄入热量已结算

## 6. 设计与开发备注

### 6.1 MVP 优先级建议
优先实现：
1. 首页
2. 商家页
3. 商品详情弹层
4. 购物车
5. 确认订单页
6. 模拟支付页
7. 等待页
8. 结果页

### 6.2 数据来源建议
MVP 使用本地静态模拟数据：
- 5 家虚拟商家
- 每家 8～12 个商品
- 商品带价格和预估热量

### 6.3 交互复杂度建议
- 地图配送先不做，使用进度条即可。
- 搜索可先做假入口，不实现真实搜索。
- 品类筛选可先静态展示。

本页面原型文档可直接用于以下场景：
1. 在 Figma 中按页面结构绘制低保真原型。
2. 在 AI UI 工具中逐页生成移动端页面。
3. 交给前端作为 MVP 页面实现说明。

建议下一步产出：
- 一套低保真线框图
- 一套页面文案表
- 一份前端组件拆解清单

---

## 8. 总结

《今晚不送达》的页面原型核心不在于把外卖界面“画得像”，而在于把以下三件事做顺：
1. 用户愿意进来点。
2. 用户愿意被等待页拖住。
3. 用户最终愿意认可结果页的价值。

只要这三个页面体验闭环成立，这个产品就具备 MVP 验证价值。
